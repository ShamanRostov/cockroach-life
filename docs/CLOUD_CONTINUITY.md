# Облако ↔ компьютер: как не потерять прогресс

**Главное правило:** прогресс живёт на **GitHub**, не в чате и не на диске облачной VM.

Пока изменения не **закоммичены и не запушены** — их можно потерять при закрытии агента, смене машины или новом запуске.

Репозиторий: https://github.com/ShamanRostov/cockroach-life  
Ветка по умолчанию: **`main`**

---

## Как устроена работа

| Где | Что происходит |
|-----|----------------|
| **Cloud Agent** (телефон / cursor.com / Cloud в Cursor) | Отдельная VM, свой клон репо, своя ветка |
| **GitHub** | Единственный «мост» между облаком и компьютером |
| **Компьютер (Cursor Desktop)** | Ваш локальный клон; видит только то, что уже на GitHub |

Cloud Agent **не пишет напрямую** в файлы на вашем ноутбуке. Он пушит ветку → вы забираете её дома.

---

## Рабочий цикл (запомните эти 4 шага)

### 1. Старт задачи в облаке

- Откройте [cursor.com/agents](https://cursor.com/agents) или приложение Cursor
- Новый Cloud Agent → репозиторий `cockroach-life`
- Опишите задачу одним сообщением

Агент сам создаёт ветку вида `cursor/...`, коммитит и пушит.

### 2. Не уходите, пока нет push

В конце задачи (или перед сменой устройства) попросите явно:

> «Закоммить и запушь все изменения на GitHub, открой PR»

Проверьте в агенте или на GitHub: появилась ветка / PR.

### 3. Продолжить на компьютере

**Вариант A — тот же агент (удобно):**

1. Откройте папку проекта в Cursor Desktop
2. Запустите **локальный** агент в этом репо
3. В **Agents Window** у облачного агента: **Move to → Local**  
   (опция появляется, когда локальный агент по этому репо уже открыт)

**Вариант B — вручную через git (надёжно всегда):**

```powershell
cd C:\путь\к\cockroach-life
git fetch origin
git checkout <имя-ветки-агента>
git pull
```

Имя ветки смотрите в PR или в шапке агента на cursor.com/agents.

### 4. После правок дома — снова на GitHub

```powershell
git add -A
git commit -m "краткое описание"
git push
```

Тогда следующий Cloud Agent (или вы с телефона) увидит ваш код.

## Правила git для этого проекта

1. **Не коммитьте в `main` напрямую из агента** — только feature-ветка + PR.
2. **Один логический блок = один commit** (или несколько мелких, но всегда с push).
3. **Перед `git pull` / сменой ветки** — убедитесь, что локальные правки закоммичены или в stash.
4. **Секреты** (токены, пароли) — только в Cursor Secrets / локальных `.env*.local`, не в git.
5. Чат агента — удобная история, но **не бэкап кода**. Бэкап = GitHub.

### Типичные команды дома

```powershell
# Актуализировать main
git checkout main
git pull origin main

# Забрать ветку агента
git fetch origin
git checkout cursor/имя-ветки
git pull

# После своих правок
git add -A
git commit -m "fix: ..."
git push

# Влить в main через GitHub PR (кнопка Merge), затем:
git checkout main
git pull origin main
```

## Частые ошибки

| Симптом | Причина | Что делать |
|---------|---------|------------|
| Дома «старый» код | Забыли `git pull` / не на той ветке | `git fetch` → checkout ветки агента или `main` |
| Агент «забыл» правки | Не было commit+push | В чате: «закоммить и запушь» |
| Конфликт при pull | Правили одни и те же файлы в двух местах | Разрешить конфликт, commit, push |
| Move to Local недоступен | Нет открытого локального агента по репо | Open Folder → локальный агент → снова Move to Local |
| Продолжили cloud-чат на ПК, файлы локально не меняются | Cloud остаётся cloud | Move to Local **или** checkout ветки вручную |
